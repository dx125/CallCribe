# CallCribe

Локальная расшифровка рабочих звонков в реальном времени под Windows.
Слушает микрофон и системный звук, режет речь по паузам, распознаёт
через `faster-whisper` и пишет текст в окно, откуда его можно скопировать.

Ничего никуда не отправляется: ни аудио, ни текст не покидают машину.
Единственный выход в сеть за всю жизнь приложения — разовая загрузка
модели при первом запуске, и [её тоже можно избежать](#установка-совсем-без-сети).

> [README.md](README.md) — the same documentation in English.

## Что нужно

Этот раздел стоит прочитать: почти всё, что может пойти не так, — здесь.

| | |
|---|---|
| **ОС** | Windows 10 или 11. Не переносится: системный звук берётся через WASAPI loopback — это Windows-специфичный API. |
| **Python** | 3.10 – 3.12. Надёжнее всего 3.11 или 3.12: у самой свежей версии часто ещё нет колеса `PyAudioWPatch`. Ниже 3.10 приложение не стартует и прямо об этом говорит. |
| **Диск** | ~2 ГБ на окружение плюс модель: около 1.6 ГБ для `large-v3-turbo`, около 3 ГБ для `large-v3`. Модели кешируются в `%USERPROFILE%\.cache\huggingface`, не в папке проекта. |
| **Интернет** | Один раз — скачать модель. Дальше приложение полностью офлайн, см. [Установка совсем без сети](#установка-совсем-без-сети). |
| **Видеокарта** | Необязательна. NVIDIA со свежим драйвером даёт запас по скорости примерно в 25 раз. Без неё всё считается на CPU, и приложение само стартует на модели полегче. Ставить CUDA-тулкит в систему не нужно — колёса несут свои DLL. |
| **Наушники** | Настоятельно рекомендуются. Через колонки голос собеседника попадает ещё и в микрофон, и каждая фраза распознаётся дважды. См. [Ограничения](#ограничения). |

## Установка

```powershell
git clone https://github.com/dx125/CallCribe.git
cd CallCribe
powershell -ExecutionPolicy Bypass -File setup.ps1
```

Это всё. `setup.ps1` находит подходящий Python, создаёт `.venv` и ставит
зависимости — с CUDA-колёсами, если видит драйвер NVIDIA, и без них, если
не видит. Если угадал неверно, решение навязывается ключом `-Gpu` или `-Cpu`.

<details>
<summary>То же самое руками</summary>

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt        # CPU
.venv\Scripts\python.exe -m pip install -r requirements-gpu.txt    # + CUDA 12, ~700 МБ
```

`requirements-gpu.txt` подключает `requirements.txt`, так что команда в
любом случае одна, а не две.
</details>

Проверьте машину до того, как понадеетесь на неё в настоящем звонке:

```powershell
.venv\Scripts\python.exe selftest.py                # быстро, без модели
.venv\Scripts\python.exe selftest.py --load-model   # ещё и загрузить whisper
```

Гоняет синтетический звук через ресемплер и VAD, проверяет фильтр
галлюцинаций и повторы, сверяет каталог надписей с кодом, гоняет
сохранение настроек и смену модели на заглушке, показывает найденные
устройства и то, куда встанет распознавание — на GPU или на CPU.

## Запуск

Один раз создайте ярлык на рабочем столе:

```powershell
powershell -ExecutionPolicy Bypass -File install-shortcut.ps1
```

Дальше запуск — двойным щелчком по ярлыку **CallCribe**, до начала звонка.

```
CallCribe.lnk (рабочий стол)  ->  pythonw.exe -m callcribe   без консоли, для обычной работы
run.cmd                       ->  python.exe  -m callcribe   с консолью, для диагностики
```

Ярлык запускает `pythonw.exe`, то есть **без окна консоли**. Так сделано
намеренно: консоль рядом с окном расшифровки легко закрыть по ошибке, а её
закрытие убивает процесс жёстко. С ярлыком единственное окно приложения —
окно расшифровки, и закрывается оно правильно.

**Первый запуск делайте через `run.cmd`**: в консоли виден ход загрузки
модели, а иначе молчаливое ожидание нескольких гигабайт неотличимо от
зависания. Через неё же удобно смотреть, если что-то ведёт себя странно.

Оба принимают ключи, задающие стартовое состояние окна:

| Ключ | Значения | Что задаёт |
|---|---|---|
| `--lang` | `ru` `en` `es` `auto` | Язык распознавания |
| `--ui-lang` | `en` `ru` | Язык интерфейса |
| `--model` | имя размера или путь к папке | Модель whisper |

Ключи ничего не требуют: всё это переключается и в самом окне. Они лишь
подставляют другое начальное значение вместо сохранённого — и работают
ровно как выпадающие списки, то есть в файл настроек попадут, как только
в окне поменяют хоть что-нибудь. Негодный путь в `--model` приложение
отвергает сразу, а не через полминуты загрузки.

Расшифровка сохраняется в
`%USERPROFILE%\call-transcripts\call_ГГГГММДД_ЧЧММСС.md`.

### Первый запуск по шагам

1. Окно открывается сразу и показывает «Загружаю модель...».
2. `faster-whisper` скачивает веса: около 1.6 ГБ на машине без
   видеокарты (`large-v3-turbo`), около 3 ГБ с видеокартой (`large-v3`).
   Разово — дальше модель берётся из локального кеша.
3. Статус меняется на «готово, слушаю (...)» с именем модели и тем,
   на `cuda` она или на `cpu`.
4. Говорите или начинайте звонок. Текст появляется через 1–3 секунды
   после конца фразы.

### Установка совсем без сети

Если машина не должна ходить в сеть вообще, принесите модель отдельно и
покажите её приложению:

1. На машине с интернетом скачайте модель, **переведённую в CTranslate2**, —
   например [`Systran/faster-whisper-large-v3`](https://huggingface.co/Systran/faster-whisper-large-v3)
   или полегче [`deepdml/faster-whisper-large-v3-turbo-ct2`](https://huggingface.co/deepdml/faster-whisper-large-v3-turbo-ct2).
   Нужны `model.bin`, `config.json` и файл токенизатора.
2. Перенесите папку.
3. Выберите её кнопкой **Browse...** в списке **Модель:** или запустите
   `run.cmd --model "D:\models\faster-whisper-large-v3"`.

Выбор запоминается, так что это разовое действие. Что делает папку
годной — см. [Выбор модели](#выбор-модели).

## Где хранится выбранное

Три вещи, которые меняют в окне, — язык интерфейса, язык распознавания и
модель — переживают перезапуск. Лежат они в

```
%APPDATA%\CallCribe\settings.json
```

Файл пишется сразу после выбора, а не при выходе: приложение живёт весь
звонок и вполне может не дожить до штатного закрытия, а терять из-за
этого выбранную модель обиднее всего. Модель при этом сохраняется только
после того, как **реально загрузилась**, — иначе неудачный выбор пережил
бы перезапуск и следующий старт начался бы с отказа.

Испорченный файл ничему не мешает: приложение скажет об этом в статусе и
возьмёт значения по умолчанию. Чтобы вернуться к тому, что записано в
`config.py`, файл достаточно удалить.

## Настройка

Всё живёт в [config.py](callcribe/config.py).

Три параметра — `ui_language`, `language` и `whisper_model` — это значения
**для первого запуска**. Дальше побеждает выбранное в окне, оно лежит в
`settings.json` (см. «Где хранится выбранное»).

| Параметр | По умолчанию | Зачем менять |
|---|---|---|
| `whisper_device` | `auto` | `cuda` / `cpu` принудительно. `auto` берёт GPU, если он есть, и сам откатывается на CPU |
| `whisper_model` | `large-v3` | Модель при первом запуске: имя размера или путь к папке. В окне меняется на ходу, см. «Выбор модели» |
| `cpu_fallback_model` | `large-v3-turbo` | Модель для старта, когда годного GPU нет. На CPU всё упирается в фиксированную стоимость вызова: `large-v3` — ~3.1 с, turbo — ~2.6 с при вшестеро меньшем наклоне. На типичных репликах в 2-5 с `large-v3` отстаёт от реального времени, turbo успевает. При смене модели из окна эта подмена не работает — там честно грузится то, что выбрали |
| `ui_language` | `en` | Язык интерфейса при первом запуске: `en` или `ru`. К языку распознавания отношения не имеет |
| `language` | `ru` | Язык **распознавания** при первом запуске — в окне он переключается на ходу, см. «Выбор языка». `None` — автоопределение |
| `restrict_auto_language` | `True` | В режиме «Авто» подменять язык вне списка ближайшим из списка. Выключайте, только если в звонках звучит что-то помимо русского, английского и испанского |
| `prompts` | по списку терминов на язык | Единственный механизм подсказки терминологии в v1. Держите здесь актуальный стек — на замере это самый действенный рычаг. В комплекте лежат термины ASP.NET / EF Core, **замените их на свои**. **Whisper молча обрезает промпт до 223 токенов** — при превышении `selftest` и запуск предупредят |
| `vad_aggressiveness` | `2` (0–3) | Выше — меньше ложных срабатываний на шум, выше риск обрезать тихую речь |
| `end_silence_ms` | `600` | Через сколько тишины фраза считается законченной |
| `soft_utterance_ms` | `8000` | С какой длины монолога начинать искать паузу для разреза. Меньше — текст появляется чаще, но фразы дробятся |
| `max_utterance_ms` | `20000` | Жёсткий предел. Больше 30000 ставить нельзя — у whisper окно ровно 30 с |
| `beam_size` | `5` | **Не понижайте.** На `beam_size=1` замерено 30% WER против 5.9%: модель не деградирует плавно, а теряет куски по 20-30 секунд целиком |
| `show_speaker_labels` | `False` | Подписи «Я» / «Собеседник» («Me» / «Them» — по языку интерфейса). Технически бесплатны — два независимых источника |
| `output_dir` | `~/call-transcripts` | Куда складывать `.md` |

## Выбор языка

Список **Речь:** в окне — **Русский · English · Español · Авто**.
Переключается прямо во время звонка: язык читается заново на каждой фразе,
поэтому смена подхватывается со следующей же реплики (включая те, что
успели встать в очередь).

Названия языков написаны на них самих и от языка интерфейса не зависят —
человек ищет в списке знакомое начертание, и «Spanish» ему в этом не
помогает. Переводится только «Авто»: это не язык, а режим.

Вместе с языком меняется и подсказка терминологии: список русских слов,
поданный при английской речи, тянет вывод обратно в русский, поэтому
промпт в `prompts` свой на каждый язык.

**«Авто» — режим второго сорта, и вот почему.** Whisper определяет язык
по каждой фразе отдельно, а не по звонку целиком. На реплике в секунду-две
он регулярно выбирает из своей сотни языков что-нибудь вроде валлийского
или корейского — и дальше не расшифровывает, а *переводит*. Поэтому:

- список ожидаемых языков известен, и промах видно сразу: если детектор
  назвал язык не из списка, берётся самый вероятный из тех, что в списке
  (`restrict_auto_language`). Стоит это дёшево — faster-whisper определяет
  язык **до** того, как начнёт декодировать, так что ошибочный проход
  закрывается, не успев ничего посчитать;
- в первый раз о такой подмене приложение говорит в статусе — это намёк,
  что язык звонка лучше выбрать явно;
- при известном языке разговора «Авто» проигрывает явному выбору всегда.
  Английские термины внутри русской речи распознаются и с «Русский».

Смысл «Авто» — звонок, где заранее не известно, на каком языке заговорят,
или где язык меняется по ходу.

## Язык интерфейса

Список **Интерфейс:** — **English · Русский**, по умолчанию английский.
Это совершенно отдельная настройка от языка распознавания: на английском
интерфейсе русский звонок разбирается ровно так же.

Переключается на ходу и без перезапуска — надписи, кнопки, статус и
сообщения перерисовываются сразу.

Особый случай — уже сохранённый файл расшифровки. Метки говорящих в нём
(`**Я**` / `**Me**`) хранятся не текстом, а признаком канала, а сам файл
при штатном закрытии пересобирается целиком. Поэтому даже если язык
переключили посреди звонка, итоговый файл выходит на одном языке — на
том, что выбран в конце.

Надписи лежат в [i18n.py](callcribe/i18n.py) одним словарём ключ ->
{en, ru}. `selftest` сверяет, что у каждого ключа есть оба языка, что
подстановки (`{model}`, `{error}`) в переводах совпадают и что множество
ключей в каталоге в точности равно множеству ключей в коде — то есть
ловит и опечатку в вызове, и забытый перевод.

Добавить третий язык — механическая работа: код в `UI_LANGUAGES` и третье
значение к каждому ключу в `MESSAGES`. `selftest` сразу покажет, что
осталось непереведённым.

## Выбор модели

Список **Модель:** содержит готовые имена, которые `faster-whisper`
скачивает сам, и пункт **Browse...** — выбрать папку с моделью на диске.

```
tiny · base · small · medium · large-v2 · large-v3 · large-v3-turbo · distil-large-v3
```

Папка годится не любая: нужна модель, **переведённая в CTranslate2**, а не
исходный `.pt` от OpenAI. Приложение проверяет папку до загрузки и требует
`model.bin`, `config.json` и токенизатор (`tokenizer.json` либо
`vocabulary.txt`/`vocabulary.json`). Токенизатор важен отдельно: без него
`faster-whisper` молча полезет за ним на Hugging Face, а в офлайн-приложении
это не отказ, а зависание. Готовый пример такой папки лежит прямо в кеше:
`%USERPROFILE%\.cache\huggingface\hub\models--*\snapshots\*`.

Выбранные папки запоминаются (последние восемь) и в следующий раз уже
стоят в списке. В самом списке от пути остаётся имя папки — полный путь
шире окна; если имена совпали, подпись уточняется родительской папкой.

Смена модели — это не присваивание, а работа на десятки секунд, и делает
её **поток распознавания**, а не окно: модель CTranslate2 принадлежит
создавшему её потоку, и обращение к ней извне роняет процесс (`0xC0000409`).
Окно кладёт заявку, поток забирает её между фразами. Отсюда поведение:

- текущая фраза договаривается на прежней модели, следующая идёт уже на новой;
- пока идёт загрузка, в статусе висит «Loading ...» — иначе десятки секунд
  тишины выглядели бы зависанием;
- прежняя модель освобождается **до** загрузки новой. Две `large-v3` разом
  — это лишние 3 ГБ, и на видеокарте средних размеров переключение просто
  не влезло бы;
- если новая не поднялась, прежняя поднимается обратно, и звонок
  продолжает расшифровываться. В настройки такой выбор не записывается —
  иначе неудача пережила бы перезапуск.

## Что сделано против галлюцинаций

Whisper обучался на субтитрах с YouTube и на тишине уверенно выдаёт куски
из этого корпуса: «Продолжение следует...», «Субтитры сделал DimaTorzok»,
«Спасибо за просмотр», `Thanks for watching`, `Suscríbete al canal`. Штампы
свои у каждого языка, поэтому список покрывает все три. При двух постоянно
открытых каналах это главный источник мусора, поэтому фильтрация
трёхслойная:

1. **webrtcvad** — сегмент вообще не доходит до модели, если в нём нет речи.
2. **Пороги внутри faster-whisper** — `vad_filter`, `no_speech_threshold`,
   `log_prob_threshold`, `compression_ratio_threshold`, плюс обрезка
   хвостовой тишины в сегменте (длинный хвост тишины провоцирует
   фантазии сильнее всего).
3. **[filters.py](callcribe/filters.py)** — явный список субтитровых
   штампов и детектор зацикливания декодера. Зацикливание бывает двух
   калибров: по слову («да да да да да...») и по целому предложению, когда
   whisper дословно повторяет фразу два-три раза подряд. Второй случай
   порог `compression_ratio` не ловит — замерено 1.6 при двух повторах и
   2.4 при трёх против порога 2.6, — поэтому обороты ищутся явно. Требуемое
   число кругов зависит от длины оборота: короткий человек повторяет и
   всерьёз («раз, два, три, раз, два, три» — реальная строка из
   расшифровки), поэтому для него нужно четыре круга, а целое предложение
   дословно дважды подряд отсекается сразу. На 896 строках сохранённых
   расшифровок это правило не задело ни одной живой строки.

Если в вашей расшифровке всплывёт штамп, которого нет в списке — допишите
его в `_EXACT_RAW` или `_MARKERS_RAW`. Маркеры (подстроки) держите
длинными: `subtítulo` одним словом отсекло бы и живой разговор про
локализацию, а `subtítulos realizados por` — только субтитровый штамп.

## Длинная речь и производительность

Замерено на RTX 4070 Ti, `large-v3`/`float16`/`beam=5`, живая русская речь:

| Длина фрагмента | Время распознавания | RTF |
|---|---|---|
| 1 с | 0.17 с | 0.17 |
| 5 с | 0.34 с | 0.07 |
| 20 с | 0.88 с | 0.04 |
| 45 с | 1.88 с | 0.04 |

То есть **фиксированные ~0.17 с на вызов плюс ~0.034 с на секунду звука**.
Фиксированная часть — это энкодер: whisper всегда работает окном ровно
30 секунд и добивает вход тишиной, поэтому секундная реплика стоит почти
столько же, сколько двадцатисекундная.

Отсюда два следствия:

- **Запас по скорости 25-кратный.** Узкое место задержки — не вычисления,
  а `end_silence_ms` (0.6 с ожидания конца фразы) плюс время до разреза
  длинного монолога. Более быстрая модель или больше VRAM этого не меняют.
- **Резать длинную речь выгодно и по точности.** Замер WER против эталона
  (102 с русской технической речи, 170 слов): весь файл целиком — 5.9%,
  нарезка на фразы — 4.1%. При `condition_on_previous_text=False` короткие
  куски не тащат за собой ошибку и каждый заново получает `initial_prompt`
  с терминами.

Что на этом замере оказалось важным, а что нет:

| Изменение | WER | Вывод |
|---|---|---|
| нарезка на фразы вместо целого файла | 5.9% -> 4.1% | заметно помогает |
| `initial_prompt` с терминами выкл -> вкл | 7.1% -> 5.9% | самый доступный рычаг |
| `beam_size` 5 -> 1 | 5.9% -> **30.0%** | никогда так не делать |
| `beam_size` 5 -> 10 | 5.9% -> 5.9% | смысла нет |
| `large-v3` -> `large-v3-turbo` (с нарезкой) | 4.1% -> 4.1% | на этом отрывке вничью, но втрое быстрее |

Провал на `beam_size=1` — не плавная деградация: модель теряет куски по
20-30 секунд целиком («Дальше по миграциям Intertiframe.org **который
висит со среды**» — между этими словами пропало полторы фразы).

Из таблицы следует, что при 25-кратном запасе по скорости менять модель
или докидывать VRAM бессмысленно: единственный рычаг, который реально
двигает точность, — держать в `initial_prompt` тот стек, который у вас
действительно звучит на звонках.

Что происходит с монологом длиннее 30 секунд:

1. До whisper он в таком виде не доходит никогда. `end_silence_ms`
   заканчивает фразу на любой паузе от 0.6 с — на живой речи это примерно
   раз в 12 секунд.
2. Если человек говорит без таких пауз, после `soft_utterance_ms` (8 с)
   сегментатор ищет **самый тихий момент** в накопленном буфере и режет
   по его середине — стык приходится между словами, а не внутрь слова.
3. Если пауз нет вообще (чтение списка вслух), на `max_utterance_ms`
   (20 с) срабатывает жёсткий предел с перехлёстом 200 мс, чтобы слово на
   стыке не пропало.

**Переполнения памяти не будет.** Буфер фразы ограничен `max_utterance_ms`
по построению: 20 с при 16 кГц float32 — это 1.28 МБ, независимо от того,
сколько человек говорит подряд. Захват, сегментация и распознавание живут
в разных потоках, так что слушать система не перестаёт, пока считает
предыдущий кусок. Расти без предела может только очередь фраз, если
распознавание окажется медленнее реального времени, — на GPU это запас в
25 раз, а на CPU приложение предупредит в статусе.

## Ограничения

- **Задержка 1–3 секунды** после конца фразы. Whisper архитектурно не
  потоковый: сегментация идёт по паузам, а не по словам. Для субтитров
  слово-в-слово нужна принципиально другая модель (например, NVIDIA
  Parakeet с cache-aware streaming).
- **Нужны наушники.** При работе через колонки голос собеседника попадает
  ещё и в микрофон, и каждая его фраза распознаётся дважды — по одному разу
  на каждом канале. Подавления такого эха в v1 нет. Так выглядит **самая
  частая причина «текст задвоился»**: две строки с одинаковым временем и
  почти одинаковым текстом. При `show_speaker_labels=False` они в файле
  неотличимы друг от друга и похожи на сбой; включите метки — и станет
  видно, что это «Я» и «Собеседник», то есть эхо.
- **Loopback ловит весь системный звук**, а не только звонок: музыка, ролик
  в браузере, уведомления — всё уедет в расшифровку. На этот случай в окне
  есть кнопка «Pause» / «Пауза».
- **Без диаризации.** В групповом звонке вся дальняя сторона — один канал
  «Собеседник», без разделения на конкретных участников.
- **Один язык на фразу.** Список языков переключает распознавание целиком;
  фраза, в которой человек переходит с русского на английский посреди
  предложения, разбирается как одноязычная. «Авто» тут не помогает — он
  определяет язык по каждой фразе, а не по её частям.
- **Bluetooth-гарнитуры в режиме hands-free (HFP)** режут частоту
  дискретизации входа до 8 кГц — качество распознавания голоса собеседника
  в такой конфигурации заметно просядет.
- **Эксклюзивный режим устройства вывода.** Если приложение захватило
  вывод монопольно, loopback не заработает — приложение покажет понятную
  ошибку при старте.
- **Микрофон необязателен**: если его нет, приложение стартует и пишет
  только собеседника, предупредив об этом.
- **Буфер обмена и закрытие окна.** Tk теряет владение буфером обмена при
  выходе, поэтому «Copy all» имеет смысл вставлять до закрытия окна.
  На сохранённый файл это не влияет — он пишется независимо.
- **Закрывать нужно окно расшифровки, а не консоль.** Консольное окно
  рядом — это лог. Если закрыть именно его, процесс убивается жёстко
  (внутри CTranslate2 сидит рантайм Intel со своим обработчиком закрытия
  консоли), и файл не пересортируется по времени. Строки при этом всё
  равно уже на диске — они пишутся сразу.

## Сохранение

Строки пишутся в `.md` **сразу по мере распознавания**, а не в конце: падение
или kill процесса не должны съедать сорокаминутный звонок. При штатном
закрытии окна файл переписывается заново, отсортированный по времени начала
фраз — два независимых канала приходят вперемешку.

## Если что-то не работает

**`setup.ps1` не запускается: «выполнение сценариев отключено».** Это
политика выполнения PowerShell по умолчанию. Команда из раздела
«Установка» уже обходит её через `-ExecutionPolicy Bypass` — это действует
только на один запуск и ничего не меняет насовсем.

**«Python 3.10 или новее не найден», хотя Python стоит.** Скорее всего,
`python` — это заглушка из Microsoft Store, которая умеет только открывать
Store. Поставьте с [python.org](https://www.python.org/downloads/windows/),
отметив «Add python.exe to PATH», либо посмотрите `py --list`.

**«Loopback-устройство не найдено» при старте.** WASAPI loopback цепляется
к *текущему устройству вывода по умолчанию*. Проиграйте что-нибудь, чтобы
убедиться, какое оно, и проверьте «Параметры → Система → Звук». Если вывод
занят приложением в монопольном режиме, освободите его и перезапустите
CallCribe.

**«не хватает библиотек счёта CUDA (cublas64_12.dll, ...)».** Видеокарта
NVIDIA и драйвер есть, а CUDA-колёс нет — чаще всего потому, что на машине
с видеокартой поставили `requirements.txt` вместо `requirements-gpu.txt`.
Одного драйвера хватает, чтобы карту было *видно*, но не чтобы на ней
считать, поэтому CallCribe проверяет библиотеки заранее и уходит на CPU.
Ничего не сломано, просто карта простаивает. Чтобы её задействовать:

```powershell
.venv\Scripts\python.exe -m pip install -r requirements-gpu.txt
```

`selftest.py` сообщает об этом же в разделе **CUDA**.

**Окно пишет, что распознавание отстаёт, и очередь растёт.** Вы на CPU со
слишком тяжёлой моделью. Возьмите `large-v3-turbo` или меньше в списке
**Модель:**. При старте с нуля приложение делает это само; но модель,
выбранную вручную, оно не подменяет.

**Текст задваивается, две почти одинаковые строки.** Эхо через колонки.
Наденьте наушники. Чтобы убедиться, поставьте `show_speaker_labels = True`
в `config.py` — станет видно «Я» и «Собеседник» вместо одной строки дважды.

**Расшифровывается музыка и ролики в браузере.** Loopback берёт всё, что
играет система. Пользуйтесь кнопкой «Пауза».

**Не появляется ничего и без ошибок.** Запустите `run.cmd` вместо ярлыка и
прочитайте консоль, затем `selftest.py` — он скажет, нашлись ли устройства
и куда встала модель.
